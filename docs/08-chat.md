# 团队聊天

直连 Matrix 的团队房间聊天——不是消息转发，是实时 sync（在线时消息、typing、在线状态全实时）。

## 房间视图

- **全部**：Element 式**单一时间序**——群聊与 DM 的消息按 `last_ts` 倒序交错，一屏看全队动态（不再分两段）
- **团队群 / DM 切换**：团队群（>2 人）与 DM 私聊顶层 Segmented 切换
- 每个房间卡显示未读/最近消息预览

## 会话内功能

| 功能 | 说明 |
|------|------|
| 线程（Thread） | Element 线程面板——长讨论收进线程，主线程不刷屏 |
| 成员卡 | 点成员头像看详情（MemberDetail：角色/状态/最近活动） |
| @提及 | 输入 `@` 出补全弹层（子串匹配，↑↓ 键盘导航，Enter 选中）——Worker 必须被 mention 才会消费消息 |
| 消息搜索 | 房间内全文搜索（MessageSearch） |
| 消息操作条 | 悬停消息出操作条（复制/跳转房间定位等） |

## 房间管理

- **收藏 / 静音**：收藏置顶、静音免打扰
- **退出 / 删除房间**：本地视图操作（退出=离开 Matrix 房间）
- **接受邀请**：新房间邀请从 [通知](./10-notifications.md) 进入——toast/通知中心的「接受」跳到团队管理完成入房

## 与 Agent 协作

- Worker/Manager 是 Matrix 用户：在房间里 @它们就是给任务/指令
- **审批**：Worker 的 Tool Guard 审批消息就发在房间里——插件检出后桌面 toast + 卡上批/拒（详见 [审批](./09-approvals.md)）
- 发送带 @ 的命令时，插件保证三重 mention 标记（m.mentions + matrix.to + 正文），Worker 消费队列不丢消息

## 离线行为

插件后端 sync 常驻：你离线期间发生的消息/审批/邀请，回来后首轮 sync 全量补检（离线通知补检机制）。
