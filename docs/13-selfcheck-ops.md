# 自检与运维

## 分层自检（L0 → L3）

出问题先跑自检——每层隔离一个故障面，绿到红的那层就是问题所在：

| 层 | 检查什么 | 红了说明 |
|----|----------|----------|
| **L0 本地环境** | 插件后端存活 + 宿主 QwenPaw 版本 | 插件没装好 / 宿主版本不兼容 |
| **L1 连通性** | 全部已配置地址（Matrix / Controller）逐个探测，带错误明细 | 网络不通 / 地址填错 / 服务没起 |
| **L2 认证与 API** | Matrix whoami + joined_rooms（+ Controller projects） | token 无效 / Human 等级不对（level 1 → 401）/ API 版本不支持 |
| **L3 房间实测** | 逐房间权限 + 发 `[selfcheck] ping` 实测 | 单房间权限/消息投递问题（会真的在房间发一条 ping，慎用生产群） |

- 每层可单独点跑，也可一键全跑（`/selfcheck/all`）
- L2 的权限自检可见**当前 Matrix 账号的权限等级**（判断 L2 模式 401 是否因 level 1）

## 运维面板

> **运行时显示位置（v0.5.0-beta.12 起）**：多运行时卡（5 静态卡 + 实时计数）已**从运维页移除**——静态清单硬编码不全、位置错。运行时管理归**团队管理**：每个 Worker 行与 Manager 表直接显示自己的 `runtime`（+ `phase` 徽章，聊天头 1:1 Worker 房间也有双徽章），数据 = Worker/Manager CR 字段，零新端点。

**集群负载**（L1 专属，可选模块）：

- 数据源 = Controller `/api/v1/status`（与 dashboard cluster-status 同源）
- SGLang / GPU 负载概览
- 后端未启用时 404 → 卡片**不渲染**（静默，不报错）——L2 模式下看不到这一模块是预期行为

## 排障顺序建议

1. L0 红 → 重装插件 / 查宿主版本（[安装与升级](./01-install.md)）
2. L1 红 → 对照配置页地址逐个核对（多地址时任一红即提示哪个）
3. L2 红 → 看错误明细：401 = 认证（token / level）；404 = 版本
4. L3 红 → 单房间问题：查该房间成员/权限，或换房间验证是否普遍
5. 都绿但功能异常 → 查 [架构与安全](./14-architecture.md) 的已知限制，再看浏览器控制台
